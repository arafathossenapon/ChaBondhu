# Pickup and collection frontend

Pickup and collection live on the existing order details page. Open **My orders** in the grower or factory dashboard, then select an order. The order summary shows the listing, participants, and estimated harvest snapshot. The pickup section shows the saved date, collection point, optional notes and transport estimate, and actual collected weight. Missing values show **Not scheduled** or **Not recorded**.

## Screen and API mapping

| Screen or action  | Endpoint                   | Request                                                                                                                                | Response and permissions                                                                                                                                                                                                                                          |
| ----------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| My orders         | `GET /orders/my`           | Query: `page`                                                                                                                          | HTTP 200, paginated `{ data, total, page, limit, totalPages }` scoped to the signed-in grower or factory.                                                                                                                                                         |
| Order details     | `GET /orders/:id`          | Order ID in the path                                                                                                                   | HTTP 200, order with listing and participant summaries, agreed price, estimated quantity, actual weight, pickup fields and independent order/payment statuses. These frontend pages are for participants. The backend also permits admins to read an order by ID. |
| Schedule pickup   | `PATCH /orders/:id/status` | `orderStatus: "PICKUP_SCHEDULED"`, `proposedCollectionDate`, `collectionPoint`, optional `pickupNotes` and `estimatedTransportCostBdt` | HTTP 200, updated order in the same shape as the detail response. The owning factory can move an `ACCEPTED` order to `PICKUP_SCHEDULED`. The service checks that the listing is still reserved.                                                                   |
| Record collection | `PATCH /orders/:id/status` | `orderStatus: "COLLECTED"`, `actualCollectedWeightKg`                                                                                  | HTTP 200, updated order with the saved weight. The owning factory can move a `PICKUP_SCHEDULED` order to `COLLECTED` while the listing remains reserved. The estimated quantity and payment status are preserved.                                                 |

## Validation and error behavior

- Pickup accepts a valid date in `YYYY-MM-DD` format and a trimmed collection point of 1–255 characters. The optional flat transport estimate accepts 0–9,999,999,999.99 BDT with up to two decimal places.
- The database stores a calendar date. The review compares it to today's date in Bangladesh and warns about a past date. The backend accepts past dates and has no pickup time, rescheduling, or grower pickup mutation.
- Actual collection accepts 0.001–9,999,999.999 kg with up to three decimal places. The form rejects excess precision before sending the original numeric value. Actual weight may differ from the estimate. The endpoint permits this transition once per order lifecycle.
- Both writes use the existing JWT session, require confirmation, and prevent another submission while a request is in progress. On success, the frontend uses the returned order and refreshes order details and history.
- Validation errors (HTTP 400) and server feedback are shown to the caller. A protected HTTP 401 clears the session through the shared API client. HTTP 403, 404 and 409 trigger a detail refresh after a write so stale controls can disappear. The backend enforces ownership and transitions.
