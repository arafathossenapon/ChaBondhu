# ChaBondhu frontend

From this directory run `pnpm install --frozen-lockfile`, copy `.env.example` to `.env.local`, then run `pnpm dev`. Set the public `VITE_API_BASE_URL` to the NestJS API URL or to a same-origin proxy prefix. Start NestJS separately for live integration. For direct browser requests, the backend's existing CORS configuration must allow the frontend origin, including its exact scheme and port. Include bearer and idempotency headers in any proxy or CORS allowlist. Private settings belong on the backend.

`pnpm build` checks TypeScript and writes `dist/`. A static host must serve `index.html` for frontend route deep links.

Run `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm test`, and `pnpm test:browser`. The browser suite uses Playwright Chromium by default (`pnpm exec playwright install chromium`), or set `PLAYWRIGHT_BROWSER_CHANNEL=msedge` to use installed Edge. The browser suite starts its own Vite server.

The landing page is public. Sign in or register as a grower or factory. The bearer session lives in memory, so refreshing or closing the tab requires sign-in again. Growers and factories can complete their required profile details. Factory owners can see verification status and rejection reasons, edit profile details, and resubmit for review. Admin accounts land on a protected admin page. Password reset, refresh tokens, marketplace pages and full dashboards are outside this milestone. The [architecture plan](../docs/frontend-architecture-plan.md) defines those boundaries.

The signed-in marketplace at /marketplace/listings supports grade and district discovery. Factory offer comparison at /marketplace/offers uses exact grade, price bounds, and API sorting. Listing details show same-grade market prices. The API does not supply a listing asking price, listing-specific offers, or a pickup booking in listing detail. Growers can open the dashboard at /grower/dashboard or manage their own harvests at /grower/listings. The dashboard counts the listings returned by the owner endpoint. The grower can publish, edit active available listings, and withdraw eligible listings. Withdrawn records retain the API status CANCELLED and remain visible to their owner. The frontend displays EXPIRED only when the API returns it. Procurement request management and pickup workflows are separate milestones.
